# 报告交付前自检清单

按顺序逐项检查，每项只有"通过"和"需修改"两种状态。

---

## 1. 干净墙检查（最重要，一票否决）

通读报告全文，搜索以下模式，有任何一个命中 → 修改：

### 1.1 对话残留

- [ ] 是否存在"根据您的要求""按照您的指示""您提到"等对用户说的内容？
- [ ] 是否存在"我已经""我整理了""我分析了""我为您"等 AI 第一人称？
- [ ] 是否存在"接下来""下面""以上是"等对报告结构的元描述？
- [ ] 是否存在"希望对您有帮助""如有问题请反馈"等客套结尾？

### 1.2 作者身份暴露

- [ ] 报告是否读起来像一份人写的正式报告（而非 AI 生成的）
- [ ] 开头是否直接进入主题（而非"本报告旨在……"这类废话开头）

### 1.3 废词清理

- 搜索"可以说""总的来说""众所周知""一定程度上""某种意义上""进行了""开展了" → 删掉或用具体表述替代

---

## 2. 结构完整性

- [ ] 报告是否有明确的标题层级（不超过 3 级）
- [ ] 是否包含了该报告类型的必含章节（对照对应 references 文件）
- [ ] 章节顺序是否符合"读者先关心什么，后关心什么"的逻辑
- [ ] 每个章节是否有明确的信息职能（不是为有而有）
- [ ] 如果删掉某个章节，报告的核心信息仍然完整吗？（如果是，那个章节可能不需要）

---

## 3. 信息密度

- [ ] 每个段落是否有明确的信息点（段首句测试）
- [ ] 是否存在"纯废话"段落（读完不知道说了什么）→ 删掉或重写
- [ ] 是否存在同样的信息在不同章节重复出现 → 合并
- [ ] 形容词（"显著""大幅""良好"）是否尽可能被具体数据替代

---

## 4. 数据与论据

- [ ] 每个重要结论是否有数据或事实支撑
- [ ] 数据是否附带对比基准（环比/同比/目标）
- [ ] 引用的数据是否标注了来源或统计口径
- [ ] 是否存在"无源之见"（个人判断包装成事实陈述）→ 加标注或改表述

---

## 5. 读者视角

- [ ] 目标读者能否在 30 秒内（扫读标题和段首句）理解报告的核心信息
- [ ] 是否有目标读者看不懂的内部术语（需要加注释或改表述）
- [ ] 报告长度是否匹配读者（高管 1-2 页，团队可更长）

---

## 6. 格式一致性

- [ ] 标题层级是否连贯（## 后面不能跳级到 ####）
- [ ] 同类元素格式是否统一（所有数据用同样的精度，所有日期用同样的格式）
- [ ] 专业术语是否前后一致（不要一会儿"用户留存率"一会儿"用户保留率"）

---

## 常见问题速查

| 问题 | 检查方法 | 修复方式 |
|------|---------|---------|
| 开头有"本报告旨在" | 搜索"本报告" | 删掉，直接从背景或结论开始 |
| 段落太长（>10句） | 目视 | 拆分为 2-3 个段落 |
| 数据没有单位 | 搜索数字 | 补充单位和对比基准 |
| 结论没有依据 | 读完每个结论句，问"为什么" | 补充数据或逻辑链条 |
| 章节标题太弱 | 只看目录页 | 让标题给出信息而非话题 |
